# PRD: 개인 음식점 리뷰 블로그 (Notion CMS 기반)

| 항목 | 내용 |
| --- | --- |
| 문서 버전 | v1.0 |
| 작성일 | 2026-11-03 |
| 프로젝트명 | 개인 음식점 리뷰 블로그 |
| 상태 | 초안 |

---

## 1. 프로젝트 개요

### 1.1 목적
Notion을 CMS(콘텐츠 관리 시스템)로 활용하여 개인 음식점 리뷰를 웹 블로그로 발행하는 프로젝트다.

### 1.2 CMS 선택 이유
- 글 작성은 익숙한 Notion에서 하고, 별도의 관리자 페이지를 만들지 않는다.
- Notion 데이터베이스에 글을 추가하거나 발행 상태를 바꾸면 블로그에 자동으로 반영된다.
- 본문은 Notion 블록 편집기를 그대로 사용하므로 사진, 목록, 제목 등 서식을 별도 작업 없이 쓸 수 있다.

### 1.3 대상 사용자
- **작성자(본인)**: Notion에서 리뷰를 작성하고 발행 상태를 관리한다.
- **독자**: 웹에서 음식점 리뷰를 찾아 읽는다. 로그인은 필요 없다.

---

## 2. 목표 및 성공 지표

| 목표 | 성공 지표 |
| --- | --- |
| Notion 작성 → 블로그 반영 자동화 | Notion에서 `발행됨`으로 바꾼 글이 재배포 없이 반영됨 (재검증 주기 내) |
| 읽기 편한 리뷰 화면 | 모바일/데스크톱 모두에서 가로 스크롤 없이 본문 읽기 가능 |
| 원하는 글을 빠르게 찾기 | 카테고리 필터로 목록 진입까지 2회 이내 클릭 |

## 3. 주요 기능

### F1. Notion 데이터베이스에서 글 목록 가져오기
- Notion API로 데이터베이스를 조회하고 Status가 `발행됨`인 글만 노출한다.
- 발행일(Published) 기준 최신순으로 정렬한다.
- **수용 기준**
  - `초안` 상태의 글은 목록과 상세 페이지 어디에서도 노출되지 않는다.
  - Notion에서 글을 발행하면 설정한 재검증 주기 안에 목록에 나타난다.

### F2. 글 상세 페이지
- 제목, 카테고리, 태그, 발행일과 본문(Notion 페이지 콘텐츠)을 표시한다.
- Notion 블록(제목, 문단, 목록, 인용, 이미지, 코드 등)을 HTML로 변환해 렌더링한다.
- **수용 기준**
  - 존재하지 않거나 `초안` 상태인 글의 주소로 접근하면 404 페이지를 보여준다.
  - 이미지는 Notion이 발급한 URL의 만료를 고려해 표시가 깨지지 않도록 처리한다 (§8 참고).

### F3. 카테고리별 필터링
- Category(select) 값별로 글 목록을 모아 보여주는 페이지를 제공한다.
- 카테고리 목록은 Notion 데이터베이스의 선택지에서 자동으로 가져온다.
- **수용 기준**
  - 카테고리 페이지에는 해당 카테고리이면서 `발행됨`인 글만 나온다.
  - 카테고리 이름을 URL에 사용할 때 한글 및 특수문자가 올바르게 인코딩된다.

### F4. 검색 기능 (MVP 제외, 후속 단계)
- 제목과 태그 기준 키워드 검색을 2단계 이후에 추가한다.
- MVP에서는 구현하지 않는다. 필요 시 Notion API 조회 결과를 서버에서 필터링하는 방식으로 시작한다.

### F5. 반응형 디자인
- 모바일(360px~), 태블릿, 데스크톱에서 레이아웃이 자연스럽게 바뀌어야 한다.
- 가로 스크롤이 생기지 않아야 하며, 터치 대상은 충분한 크기를 가진다.

## 5. Notion 데이터베이스 구조

| 속성명 | Notion 타입 | 설명 | 필수 | 예시 |
| --- | --- | --- | --- | --- |
| Title | title | 글 제목 (음식점 이름 + 리뷰 제목 등) | O | 성수동 마라탕 집 방문기 |
| Category | select | 카테고리 (예: 한식, 양식, 카페) | O | 한식 |
| Tags | multi_select | 태그 (메뉴, 지역, 분위기 등) | X | 웨이팅, 혼밥 |
| Published | date | 발행일 | O | 2026-11-01 |
| Status | select | `초안` 또는 `발행됨` | O | 발행됨 |
| Content | 페이지 본문 (블록) | 리뷰 본문. 데이터베이스 행(페이지)의 콘텐츠 영역 | O | - |

### 5.1 데이터 규칙
- 블로그에 노출되는 조건은 **Status = `발행됨`** 하나다.
- Category가 비어 있는 글은 `발행됨`이어도 카테고리 페이지에서 제외하고, 목록과 상세에서는 노출한다.
- Published가 비어 있으면 정렬 시 가장 뒤에 둔다.

## 6. 화면 구성

| 화면 | 경로 (예시) | 주요 내용 |
| --- | --- | --- |
| 홈 | `/` | 최근 발행된 글 목록 (카드형), 카테고리 바로가기 |
| 글 상세 | `/posts/[slug]` | 제목, 카테고리, 태그, 발행일, 본문 |
| 카테고리 | `/category/[name]` | 선택한 카테고리의 발행된 글 목록 |
| 404 | - | 글을 찾을 수 없을 때 안내 및 홈 링크 |

### 6.1 공통 레이아웃
- 상단 헤더: 블로그 이름, 카테고리 메뉴 (모바일에서는 메뉴 버튼으로 접힘)
- 하단 푸터: 간단한 저작 정보

## 7. 아키텍처 및 데이터 흐름

```
[Notion 데이터베이스]
        │  Notion API (@notionhq/client)
        ▼
[Next.js 서버 컴포넌트 / 데이터 함수]  ── 상태 필터(발행됨) ──▶  목록/상세 데이터
        │
        ▼
[렌더링 (Notion 블록 → HTML)]  ──  재검증(ISR, revalidate) ──▶  [Vercel 배포 페이지]
```

- Notion API 키와 데이터베이스 ID는 환경변수로 관리한다 (`NOTION_API_KEY`, `NOTION_DATABASE_ID`). 저장소에 커밋하지 않는다.
- 데이터 조회는 서버에서만 수행하여 API 키가 브라우저에 노출되지 않게 한다.
- 페이지는 정적 생성 후 일정 주기로 재검증하여 Notion 변경 사항을 반영한다. 재검증 주기는 구현 단계에서 확정한다.

## 8. 비기능 요구사항

| 구분 | 요구사항 |
| --- | --- |
| 반응형 | 360px 이상 모든 화면에서 가로 스크롤이 없어야 한다. |
| 성능 | 목록 및 상세 페이지는 캐시를 활용하여 Notion API 호출을 최소화한다. |
| 이미지 | Notion 파일 URL은 약 1시간 후 만료되므로, 이미지는 재검증 주기 안에서 갱신되도록 하거나 서버에서 내려받아 저장하는 방식을 검토한다. |
| 접근성 | 이미지에 대체 텍스트를 제공하고, 색 대비와 키보드 탐색을 지원한다. |
| 보안 | API 키는 환경변수로만 관리하고 클라이언트에 노출하지 않는다. |
| SEO | 페이지별 `title`, `description`, Open Graph 메타 정보를 제공한다. |
| 오류 처리 | Notion API 실패 시 빈 화면 대신 오류 안내를 보여주고 서버 로그를 남긴다. |
